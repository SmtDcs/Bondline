## What this does and does not prove

Both builds use `cargo near build non-reproducible-wasm`, so rebuilding `contract/src` or `contract-v2/src` yourself will usually
give a different hash. What holds: **the code deployed on testnet is the committed wasm file** (the file's sha256 and the account's
`code_hash` agree). It is not shown to be a byte-for-byte rebuild of the committed source. To tie behaviour to the source, run
`cargo test` in each crate and `npm run verify:live-run`; a unit test requires the committed v2 wasm to be the one the latest live
round recorded.

Check the on-chain hash yourself (read-only, no keys):

    curl -s https://rpc.testnet.fastnear.com -H 'content-type: application/json' \
      -d '{"jsonrpc":"2.0","id":1,"method":"query","params":{"request_type":"view_account","finality":"final","account_id":"v2.cbp-sm1110.testnet"}}'

and compare `code_hash` (base58) with the sha256 above.

## Mock token

`sm1110-tusdc.testnet` runs the contract in `token/` (NEP-141 + NEP-145 + NEP-148 on `near-contract-standards` 5.30.1, owner-only
`mint`). Its on-chain `code_hash` is `7vSigJRHoWcQp8LsYAWypgtVQJEFU4shQNoGQGYc79yr` = sha256
`66d6fc0a1c29683a8802bda397e8448ead45c74df1d591cc5ddf2b6d213570c1` (deploy tx `2b3hMb4qHXo3XFan4y4gCG3zow5MEaQCzvg1eYrJgBDJ`).
The deployed wasm is not committed and the build is not reproducible, so a local build of `token/` gives a different hash; the
deployed token's behaviour can be checked through its views (`ft_metadata`, `ft_balance_of`, `storage_balance_of`) and the recorded
live run.
